# Данные и признаки

[К навигации ML](../../README.md)

## Причинный пайплайн

[FeatureBuilder](../../runtime/stream.py) сохраняет исходные события, включая invalid GPS и дробные секунды. На прогнозе доступны только уже полученные события с `event_time ≤ T`. Reset replay сбрасывает ML-историю и matcher.

Используется отдельный matcher с сохранённым каталогом обучения; поведение matcher дашборда не заменяется. Хранятся 20 минут телеметрии плюс последние старые пакет и валидный GPS для возраста данных. Множества обработанных пакетов и навигационных событий растут до reset — не всё состояние ограничено этим окном.

[Маршрутные признаки](../../runtime/features.py) используют плановое расписание, правильный порядок lon/lat, плановую предыдущую остановку и целый час. [Пространственные признаки](../../runtime/spatial.py) описывают положение на маршруте и missing-маски.

## TS2Vec

[Окно](../../runtime/sequences.py) содержит 45 шагов с интервалом 20 секунд в 15-минутном горизонте. Семь каналов: скорость / 50, sin/cos курса, валидность GPS, возраст / 60, восточное и северное смещения / 100.

Окно строится из исходной GPS-телеметрии, а не из положения после map matching. Matching даёт отдельные признаки CatBoost. Сохранённые mean/scale encoder применяет в ML-сервисе; результат — 32 признака для гибридного CatBoost.

## HTTP-контракт

[PredictionRequest](../../runtime/schema.py), `schema_version=2`, содержит контекст прогнозной точки, ровно 62 маршрутных поля, служебный sequence ID и окно 45×7. Признаки отсутствующих значений передаются как JSON null, недоступные события окна — `age=1`. Горизонт: `(600, 900]` секунд.

Сервис добавляет 6 run/dwell-признаков, в ансамбле — ещё 32 TS2Vec-признака. Ответ: `prediction_delay_s`, `late_probability` (сейчас null), `model_version`. HTTP округляет задержку до трёх знаков; эквивалентность проверяют до округления.
